# 细胞像素索引原型：2026-11-13

结论：**确认纯模型吞吐和事件延迟有收益；目前保留默认关闭的原型，没有推广到其他优化。浏览器 FPS 收益尚未确认。**

## 修改及边界

`src/model.js` 的 `Simulation` 新增可选的 `pixelIndex: true`，默认 `false`。不属于生物学参数，不加入 UI 或实验配置。普通启动仍走原有路径。

- 每个细胞保存像素成员数组，另用 `Uint32Array` 保存每个格点在成员数组中的位置；新增和交换删除均为 O(1)。索引监听器在 fast/WASM 捕获监听器之前注册，支持顺序 JS、WASM 批量提交、完整监听器回放及 WASM 出错回退。
- 在分裂、分裂回滚、连通分量检查、死亡清除和死亡残片脱落时，仅取对应细胞的像素。事件查询排序为原有的 x-major 遍历顺序，保持像素修改、质心浮点累加和随机轨迹的一致性。
- 分裂仍调用 Artistoo 原有算法和质心计算方法；只在该次调用内提供目标细胞所需的像素与质心缓存，结束或抛错后清空临时缓存。没有修改 vendor、C/WASM、复制尝试次数、能量项、周期、死亡规则或物理精细度。
- 索引要对每次像素变化记账，收益已包含这部分成本。1024×768 格点下 slot 数组约 **4.003 MiB**，另有像素成员 JS 数组及元数据；这不是索引总内存测量。索引不会消除正常机械步的成本。

## 模型配对结果

机器：Apple M5，macOS，Node v24.22.1。基线为 Git 提交 `2a55e9e4b16a408025ea05381359df58c032673c` 的原始 `src/model.js`，原型源码 SHA-256 记录于原始 JSON。两者使用相同的现有依赖和 WASM。

热肿瘤场景、循环边界，种子 **29、17、77**，所有生物学机制开启。每个场景/种子使用独立进程；基线和原型在同一线程、同一 JS realm 内交替先后顺序。安装 WASM 后预热 64 MCS，再测 **6 个连续窗口 × 160 MCS**。计时包含每步索引维护、分裂、死亡等完整模型工作，不含快照、绘图及状态校验。两侧均安装相同的单步及分裂/清除计时器，没有启用 CPU profiler。窗口前 GC，计时循环内不强制 GC。

| 实际格点 | 吞吐 MCS/s，基线→原型（三种子合并） | 各种子的吞吐提升范围 | P99 单步耗时，基线→原型（三种子合并） |
| --- | ---: | ---: | ---: |
| 360×270，默认精细度 | 343.8 → 362.3 | +4.7%～6.0% | 8.59 → 5.74 ms |
| 1024×768，最高密度 | 63.0 → 65.2 | +1.9%～6.0% | 43.79 → 25.51 ms |
| 960×720，高精细度 | 125.5 → 143.8 | +13.8%～15.5% | 44.44 → 13.75 ms |

合并吞吐为总 MCS / 总耗时；P99 对所有单步样本重新计算。范围是三个种子的观测范围，不是置信区间。连续窗口有相同的演化历史，不能当作独立重复。

两个大网格场景分别有 2,880 个计时步骤/版本，合计 5,760 步：**超过 50 ms 的步骤从 46 次降为 1 次；超过 100 ms 的步骤从 11 次降为 0 次**。这衡量 Worker 内模型步骤的延迟尖峰，不等于浏览器实际帧间隔。

| 大网格事件调用 | 样本数 | 平均耗时，基线→原型 |
| --- | ---: | ---: |
| 1024×768 分裂调用（含失败尝试） | 10 | 83.40 → 2.68 ms |
| 1024×768 清除调用 | 54 | 26.82 → 0.46 ms |
| 960×720 分裂调用（含失败尝试） | 25 | 78.69 → 3.39 ms |
| 960×720 清除调用 | 49 | 24.92 → 1.29 ms |

事件很少发生的时间段，索引维护开销仍存在；不能把事件调用的几十倍加速外推为整个模型几十倍加速，也不能从这些短期观测保证任意场景的吞吐提升。

## 浏览器测试限制

已尝试在同一 Ego Lite / Chromium 156 页面交替运行开关索引的真实 Worker、WebGL、传输和 UI 路径，固定 1920×1440 显示、8× 请求速度、CPU 微环境。页面仍出现约 **1 张新画面/秒** 的后台/遮挡调度现象，与模型吞吐不匹配。激活窗口、CDP 前台及焦点模拟后的短复测仍未消除。

因此 **全部浏览器帧率和帧间隔结果作废，不用作优化收益证据**。初始仅看 rAF 中位数的检查不够严格，探针现加入 rAF P95、实际新画面频率和焦点/可见性检查，检测失败立即停止。后台记录保留用于追溯，所有记录明确标为无效。

仍需在能够保持正常前台调度的浏览器中复测，才能确认实际画面 FPS 和帧间隔收益。此次已确认的是模型执行净收益和模型步骤卡顿改善。

## 复现与原始数据

在项目根目录使用 Node 24 或更高版本：

```sh
node --test tests/pixel-index.test.mjs
node scripts/benchmark-pixel-index.mjs --case=default,maximum,fine --seeds=29 --out=reports/pixel-index/node-seed29.json
node scripts/benchmark-pixel-index.mjs --case=default,maximum,fine --seeds=17,77 --out=reports/pixel-index/node-seed17-77.json
node scripts/build.mjs
node scripts/verify-build.mjs
```

本机本次实际使用的 Node 路径为 `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node`；若 `node` 不在 PATH 中，用该绝对路径替换上述命令的 `node`。复测时不要同时运行测试套件或另一个性能基准；历史输出需要保留时通过 `--out` 另选文件名。

- `node-seed29.json`、`node-seed17-77.json`：配置、源码指纹、各窗口哈希、每个模型步骤耗时及全部事件调用耗时。
- `summary.json`：三种子合并指标。
- `browser-rejected-background.json`：首次浏览器测试的无效记录。
- `browser-calibration.json`：调整前台条件后仍未通过调度检查的记录。
- `validation.json`：测试、构建及当前产物指纹。

浏览器探针为 `scripts/pixel-index-browser-probe.js`。先构建并用 `node scripts/serve.mjs --port=4176` 启动本地页面，使用 ego-browser 将探针注入该页面；调用 `pixelIndexBrowserProbe.start()`，随后读取其 `running/status/error/rows`。它通过应用现有 RPC 选择 `pixelIndex`，没有更改生产 Worker 的时钟或绘图调度。只有通过调度检查的配对结果才可用于比较；停止后调用 `dispose()` 恢复测量挂钩。

下一步边界：保留此原型供审查；先完成有效前台帧间隔验证和更长时间的演化测试，再决定是否默认启用。此结果不支持承诺数量级扩容，也不构成推进其他架构改造的依据。
